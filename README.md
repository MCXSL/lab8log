# Лабораторная работа №8 — обход графа в ширину

Простой проект на C++17 и CMake. Выполнены основное задание и задания со звёздочкой.

## Сборка и запуск

Нужны CMake и компилятор C++.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

Для MinGW в Windows запуск: `./build/lab8.exe`.
Для Visual Studio: `./build/Release/lab8.exe`.
Для Linux: `./build/lab8`.
В CLion достаточно открыть папку проекта с CMakeLists.txt и запустить цель lab8.

## Что делает программа

1. Запрашивает число вершин от 1 до 100 (ограничение для удобства вывода).
2. Генерирует случайную симметричную матрицу из нулей и единиц. Петли отсутствуют, вероятность каждого ребра — 1/2.
3. Выводит матрицу и результат BFS с `std::queue`.
4. Строит и выводит списки смежности, выполняет BFS по ним.
5. Выполняет BFS по матрице с собственной очередью на односвязном списке.
6. Измеряет время двух матричных реализаций для 100, 500, 1000 и 2000 вершин, усредняя 10 запусков.

Внутри программы вершины нумеруются с нуля, при выводе — с единицы.
Обход начинается с вершины 1. Соседи просматриваются в порядке возрастания номеров.
Если граф несвязный, обход продолжается с первой непосещённой вершины.
Все три реализации дают одинаковый порядок для одного графа.

## Файлы

- `main.cpp` — ввод и вызовы функций.
- `Graph.h`, `Graph.cpp` — генерация, вывод, три обхода и измерение времени.
- `LinkedQueue.h`, `LinkedQueue.cpp` — собственная очередь.
- `CMakeLists.txt` — настройки сборки.

## Объяснение алгоритма

Начальную вершину помещаем в очередь и отмечаем посещённой. Пока очередь не пуста,
извлекаем первую вершину, сохраняем её в результат и добавляем в очередь всех её
непосещённых соседей. Соседа отмечаем сразу при добавлении, чтобы не добавить повторно.
В исходном псевдокоде пункт 2.12 содержит опечатку: нужно помечать `NUM[i]`, а не `NUM[v]`.

Очередь работает по принципу «первым пришёл — первым вышел», поэтому вершины
обрабатываются по уровням расстояния от начальной вершины своей компоненты.
Собственная очередь хранит указатели на первый и последний узлы. Добавление и
удаление занимают O(1), деструктор освобождает оставшиеся узлы.
Исходники лабораторной №3 не предоставлены, поэтому список реализован здесь заново.

## Сравнение времени и вывод

Для каждой размерности обе матричные реализации обходят один и тот же граф.
Генерация графа и печать не входят в замер; создание служебных массивов и результата входит.
Программа проверяет совпадение результатов измеряемых обходов.
Числа в таблице зависят от компьютера, оптимизации и нагрузки; сравнивать следует сборку Release.

Для матрицы время обхода O(V²), так как для каждой вершины просматривается вся строка.
Для списков смежности время O(V + E), где V — число вершин, E — число рёбер.
Дополнительная память BFS — O(V). Матрица занимает O(V²), списки — O(V + E).
Замена очереди не меняет порядок сложности матричного обхода. Разница времени связана
с реализацией контейнеров и выделением памяти для отдельных узлов собственной очереди.
Поэтому заранее утверждать, какая очередь быстрее на конкретном компьютере, нельзя.
